# 발주자 플레이 검수

LEAD가 “M_n 완료”라고 보고하면 이 문서를 연다.

자동화 테스트가 통과한 뒤에, **사람이 직접 접속해서** 확인하는 절차다.
코드·YAML·CI는 보지 않아도 된다. 보는 것은 화면의 문장과 손맛이다.

PLAN.md §9.5 공식 검수는 **M2, M4, M6**다. M0·M1·M3·M5도 같은 형식으로
짧게 확인한다. 공식 게이트가 아니어도 “이제 뭘 해보면 되지?”가 비면 안 된다.

관련: [PLAN.md](../PLAN.md) §5 완료 기준, [DECISIONS.md](DECISIONS.md),
[QUESTIONS.md](QUESTIONS.md), [WIRE-PROTOCOL.md](WIRE-PROTOCOL.md).

---

## 1. 한 줄로

| 단계 | 지금 | 당신이 확인할 한 가지 |
|---|---|---|
| M0 | 완료 | 두 창에서 서로 말이 보인다 |
| M1 | 완료 | 마을을 걸으며 방 묘사를 읽는다 |
| **M2** | **공식 검수** | 대장 캐릭터와 말솜씨 캐릭터가 **다른 게임**처럼 느껴진다 |
| M3 | 미착수 | 칼 없이 채집·제작·교역만으로 자산과 호칭 |
| **M4** | 미착수 | 1부 피날레까지, 무력/기술/사회 **세 길** 모두 |
| M5 | 미착수 | 5인 지부 원정 + 밀무역만으로 신뢰가 오른다 |
| **M6** | 미착수 | 웹으로 플레이 가능, 동접 숫자는 LEAD 리포트 |

미착수 절의 명령은 LEAD가 그 마일스톤을 넘길 때 이 문서에 채운다.
그때까지는 **판정 질문**만 있다.

## 2. 서버 켜기

저장소 루트에서:

```bash
git pull
go run ./cmd/server
```

로그에 `telnet listening` 과 포트가 찍힌다. 기본은 `:4001`. OrbStack 등이
4000을 쓰고 있으면 4001로 열린다. 다른 포트면 그 숫자를 쓴다.

계정은 기본이 **메모리**다. 서버를 끄면 캐릭터가 사라진다. 검수 중간에
재시작하지 말 것. 남겨 두고 싶으면 Postgres를 띄운 뒤:

```bash
docker compose up -d postgres
DATABASE_URL='postgres://yeomyeong:yeomyeong@127.0.0.1:5432/yeomyeong?sslmode=disable' \
  go run ./cmd/server
```

비밀번호는 **8자 이상**. 이름은 한글·영문·숫자·밑줄, 2–16글자.

## 3. 접속

한글 입력은 **`nc`** 를 쓴다. macOS `telnet` 은 한글 IME가 깨진다 (D-038).

```bash
nc localhost 4001
```

배너:

```
여명 · YEOMYEONG
한글이 깨지면: nc localhost 4001
이름:
```

없는 이름이면 `새로 만드시겠습니까? (y/n)` → `y` → 암호를 한 번 더.
`비밀번호:` 줄에서는 글자가 화면에 찍히지 않아야 한다.

두 캐릭터가 필요하면 터미널을 하나 더 연다. `말` 은 **같은 방**에만 들린다.

웹(`http://localhost:8080`)은 M6 전엔 검수 경로가 아니다.

## 4. 지금 쓸 수 있는 말

| 입력 | 하는 일 |
|---|---|
| `보다` / `살펴` / `look` / `l` | 방 다시 읽기 |
| `n` `s` `e` `w` / `북` `남` `동` `서` | 이동 |
| `말 <내용>` / `say <내용>` | 같은 방 대화 |
| `숙련` / `skills` | 호칭·숙련·능력 |
| `소지` / `inv` | 가방·장비 |
| `두드리다` / `이야기하다` / … | 그 자리에서 하는 일 (숙련) |
| `집다 <이름>` / `get` | 바닥에서 집기 |
| `들다 <이름>` / `equip` | 손에 들기 |
| `놓다` / `벗다` | 내려놓기 / 장비 해제 |
| `종료` / `quit` | 나가기 |

없는 출구: `그쪽으로는 갈 수 없습니다.`
모르는 말: `무슨 말인지 모르겠습니다. 보다, 종료`

## 5. 피드백 세 종류

섞지 말고 종류를 밝힌다.

| 종류 | 예 | LEAD가 하는 일 |
|---|---|---|
| **결함** | 암호가 화면에 찍힌다. `보다`가 쓰레기 문자가 된다. 방이 안 나온다. | 이슈로 받고 고친다. 게이트 실패. |
| **완료 기준 미달** | “두 캐릭터가 같은 반복처럼 느껴진다.” PLAN §5 문장을 인용. | 마일스톤을 닫지 않는다. 구체적 결함 목록. |
| **취향·제안** | 문장이 밋밋하다. 이런 명령이 있으면 좋겠다. | 듣는다. **반려 사유가 아니다.** `PROPOSALS.md` 또는 다음 검수에 묶는다. |

좋은 결함 한 줄:

> M2. `nc localhost 4001`. 계정 `대장갑`. 대장간에서 `두드리다` 30번.
> 기대: `불리는 이름: 달빛골의 대장장이`. 실제: 계속 `불리는 이름: 아무개`.

나쁜 한 줄: “뭔가 이상해요.”

문체·취향은 환영하되, 문체 가이드(실존 고유명사·잔혹 직접 묘사)를
깨지 않는 한 마일스톤을 되돌리지 않는다.

### 회신 템플릿

채팅이든 이슈든 이 칸만 채우면 된다.

```
마일스톤: M2
접속: nc localhost 4001
계정: 대장갑 / 말꾼
한 줄 판정: 통과 / 미달 / 결함
재현:
기대:
실제:
체감 (한 문장):
다음 단계로 가도 되나?: yes / no
취향 (선택):
```

공식 검수(M2/M4/M6)의 `yes`가 있어야 LEAD가 다음 마일스톤을 연다.
`no`이면 이유를 위 세 종류 중 하나로 적는다.

## 6. M0 — 골격 (완료)

**완료 기준:** 두 클라이언트가 동시 접속해 대화한다.

1. 서버를 켠다. 창을 두 개 연다.
2. 각각 `nc localhost 4001` 로 계정을 만든다. 이름을 다르게.
3. 둘 다 같은 방(처음은 `달빛골 마을문`)에 있는 채로 `말 안녕`.
4. 양쪽 화면에 `[말] <이름>: 안녕` 이 보인다.
5. 한쪽 `종료`. 다른쪽에 `<이름> 님이 나갔습니다.`

**판정:** 두 창이 서로의 말을 보면 통과. 한쪽만 보이거나 접속이 안 되면 결함.

---

## 7. M1 — 세계 (완료)

**완료 기준:** 신규 유저가 달빛골을 걸으며 묘사를 읽는다.

1. 계정 하나. 앉으면 `달빛골 마을문` 카드(이름·묘사·출구).
2. `n` `n` `e` `n` `n` `n` 정도로 걸어 본다. 매 이동마다 새 방 이름과
   2–4문장 묘사, `출구:` 줄.
3. 없는 방향(`u` 등) → `그쪽으로는 갈 수 없습니다.`
4. 두세 방의 문장을 소리 내어 읽어 본다. 오감이 두 개 이상인가.
   같은 비유가 반복되는가. 실존 인물·단체·다른 작품 고유명사가 섞였는가.

**판정:** 마을이 읽히면 통과. 빈 방, 영어만 나오는 방, 막다른 출구 표기는 결함.
문장이 마음에 안 들면 취향으로 적고, 고유명사 누수는 결함이다.

## 8. M2 — 숙련 (공식 검수 · 현재)

**완료 기준:** 서로 다른 숙련 조합의 두 캐릭터가 **체감상 다른 게임**을 한다.

전투 라운드는 아직 없다 (D-032). `lock` / `down` 도 없다 (D-033).
하는 일은 **그 자리의 일**이다. 대장간에서는 `두드리다`, 다방에서는
`이야기하다`. `익히다 대장` 은 쓰지 않는다.

불리는 이름이 곧 정체성이다. `기술` 줄은 `대장 초보`처럼 이름과 경지만 보인다.

### 8.1 캐릭터 A — 대장

```text
nc localhost 4001
이름: 대장갑
비밀번호: password1          ← 안 보여야 함
y
비밀번호: password1

보다                     ← 달빛골 마을문
n                        ← 마을문 안길
n                        ← 장터 뒷골목
e                        ← 남쪽 큰길
n                        ← 식자 마당
n                        ← 인쇄골목
n                        ← 대장간
집다 쇠망치
들다 쇠망치
두드리다
```

`두드리다` 를 반복한다. 모루가 울리거나, 빗나가거나 — **숫자가 나오면
안 된다.** 실패 문장도 정상이다. 너무 빨리 치면 `너무 빨리 입력했습니다`가 나온다.
한 박자 쉬고 다시.

15번 성공하면 호칭이 바뀐다.

```text
숙련
```

기대: `불리는 이름: 달빛골의 대장장이`, `기술: 대장 초보`.
사람들이 대장장이라고 부르는 한 줄이 먼저 나와야 한다.

### 8.2 캐릭터 B — 말솜씨

서버를 끄지 않은 채 창을 하나 더.

```text
nc localhost 4001
이름: 말꾼
비밀번호: password1
y
비밀번호: password1

n
n
e
n                        ← 식자 마당
e                        ← 다방 백야
이야기하다
```

`이야기하다` 를 반복한다. 손님이 듣거나, 말이 김에 묻히거나 —
대장간의 모루 소리와 **다른 문장**이어야 한다. 그다음 `숙련`.

기대: `불리는 이름: 말 잘하는 사람`. A의 이름이 여기 있으면 안 된다.

원하면 같은 방에 모아 `말` 로 인사해 본다. 다른 방이면 들리지 않는 것이 맞다.

### 8.3 물어볼 것

- A를 할 때와 B를 할 때 **다른 사람**이 된 느낌이 있는가.
- 익히기가 “버튼을 눌러 숫자를 올리는 일”로만 느껴지는가, 장소·도구가
  의미 있는가.
- 레벨, 경험치 바, 직업 선택 화면이 **없는가** (있으면 원칙 위반).
- 전투를 해야만 숙련이 오르는 구간이 있는가 (있으면 미달).

**판정:** 두 호칭이 다르고, 다시 접속한다면 두 사람을 다른 이유로 키우고
싶으면 통과. 같은 반복의 껍질만 다르면 미달.

## 9. M3 — 생업 (미착수)

**완료 기준:** 전투 0회로 채집·제작·교역만 해서 자산과 호칭을 얻는다.

LEAD가 M3를 넘길 때 이 절에 사는 곳 / 만드는 명령 / 파는 곳을 적는다.
그때 당신이 하는 일:

1. **칼을 뽑지 않는다.** 채집 → 제작 → 판매(또는 운반)만.
2. 주머니나 장부에 자산이 늘었는지 본다.
3. 호칭이 생업 쪽으로 바뀌었는지 본다.
4. 시세가 방마다 또는 때마다 달라 보이는지 — 고정 숫자 가게인지.
5. 막히는 지점이 있으면, 우회가 말·기술·우회로인지, 때리는 수밖에 없는지.

**판정 질문**

- 전투 없이 오늘 저녁의 한 판이 성립하는가.
- 보부상/점포가 “세계가 돈으로 숨 쉰다”고 느껴지는가, 상점 NPC 한 줄인가.
- 다음 마일스톤(서사)으로 가도 생업이 장난감으로 남지 않겠는가.

## 10. M4 — 서사 (공식 검수)

**완료 기준:** 1부 피날레 「검은 밤」에 도달하고, 무력·기술·사회 **세 경로
모두**로 클리어할 수 있다. 전투 0회 경로가 살아 있어야 한다.

LEAD가 넘길 때 첨부할 것: 검수용 서버(또는 `go run` 한 줄), 1부 비트 목록,
세 경로의 첫 명령, 복선 원장 요약.

당신이 하는 일 (경로마다 새 캐릭터 또는 안내받은 세이브):

1. 표층 활극만 따라가도 「검은 밤」에 닿는가.
2. **무력**으로 한 번, **기술/제작**으로 한 번, **말/사회**로 한 번.
3. 한 경로는 전투를 한 번도 하지 않는다. 막히면 그 지점을 적는다.
4. 청람 선생과 두 번 이상 이야기한다. 두 번째에 첫 번째를 기억하는가.
   아직 열어선 안 되는 비밀을 먼저 말하는가.
5. 반전이 뜬금없는가. 예전에 본 신문·사물·대화가 다시 읽히는가.
6. 고문·학살의 직접 묘사, 실존 인물/단체명이 있는가.

**판정 질문**

- 세 길이 진짜 다른 플레이인가, 엔딩 직전 선택지 세 개인가.
- 전투 없이 1부가 끝나는가.
- “치밀하다”가 복선 회수에서 오는가, 설명문에서 오는가.
- 홍보해도 되는 1부가 있는가 (`yes`면 M5를 연다).

## 11. M5 — 조직 (미착수)

**완료 기준:** 5인 지부가 첫 쇠말뚝 원정을 클리어하고, 밀무역만으로 신뢰
등급이 오른다.

LEAD가 넘길 때: 지부 만드는 법, 5인 모으는 법(혼자면 봇/더미 안내),
밀무역 한 줄 레시피, 원정 입구.

당신이 하는 일:

1. 지부를 만들고 다섯이 같은 목표를 본다.
2. **밀무역만** 해서 신뢰가 오르는지 — 때리지 않고.
3. 첫 쇠말뚝 원정. 막히면 3해법(무력/기술/사회)이 보이는가.
4. 한벽일보(또는 주간 신문)가 당신 행동의 흔적을 남기는가.
5. 탄압 수위가 “세계가 반응한다”고 느껴지는가, 디버그 숫자인가.

**판정 질문**

- 혼자 만렙 찍는 게임으로 다시 접히지 않았는가.
- 밀무역이 본편인가, 곁가지 재화인가.
- 원정이 파티 없이 클리어 강제인가.

## 12. M6 — 알파 (공식 검수)

**완료 기준:** 웹 클라이언트로 플레이 가능. 동접 500 시뮬에서 틱 100ms,
경제 지표 안정 — **숫자는 LEAD 리포트**. 당신은 웹으로 한 판을 한다.

LEAD가 넘길 때: URL, 계정, 웹에서 M2+M3+M4의 핵심 한 바퀴, 부하 숫자.

당신이 하는 일:

1. 브라우저만으로 계정 만들고 마을에 선다. 텔넷이 필수면 미달.
2. 지도/탭이 텍스트를 가리지 않는가. 읽는 맛이 남는가.
3. M4 경로 하나를 웹에서 끝까지.
4. 시세·숙련·대화가 웹과 텔넷에서 같은 세계인가.
5. 끊김, 중복 입력, 암호 노출, 한글 깨짐을 적는다.

동접 500은 직접 재현하지 않는다. 리포트의 틱/물가 숫자가 범위 안인지,
그리고 **손맛이 알파로 내놓아도 되는 수준인지** 만 말한다.

**판정 질문**

- 지인에게 URL을 보내도 되는가.
- 아직 부끄러운 한 화면이 어딘가. (취향으로 적어도 된다.)
- `yes`면 홍보 논의를 연다 (D-008).

## 13. LEAD가 검수 요청할 때 붙이는 것

매 마일스톤 완료 보고에 아래를 붙인다. 없으면 발주자는 검수를 시작하지 않아도 된다.

1. 이 문서의 해당 절 (명령이 비어 있으면 LEAD가 채운 뒤).
2. 커밋/브랜치 (`main` 이 기본).
3. 서버 한 줄 (`go run ./cmd/server` 또는 URL).
4. PLAN §5 완료 기준 문장 그대로.
5. 알려진 미완 (이번 판정에서 무시할 것).
6. 한 페이지 요약: 무엇을 넣었고, 무엇을 넣지 않았는가.

발주자 회신이 오면 LEAD는 통과를 `DECISIONS.md`에 기록하고 다음 마일스톤을
연다. 미달이면 결함 목록만 적고 같은 마일스톤에 남는다.
